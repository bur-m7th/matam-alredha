# نظام العضوية والانتخابات — مأتم الرضا عليه السلام - المالكية

نظام متكامل لاستقبال طلبات العضوية بالجمعية العمومية وإدارتها، ولإجراء انتخابات مجلس الإدارة.
الواجهة بالكامل باللغة العربية ومن اليمين إلى اليسار، وتعمل على الهواتف والأجهزة اللوحية وأجهزة الحاسب.

## نظرة عامة

| العنصر | التفصيل |
|---|---|
| لغة الخادم | Go 1.22 |
| الواجهة | JavaScript حديث (ES modules) بدون أي إطار عمل |
| قاعدة البيانات | SQLite داخل مجلد البيانات |
| المسارات العامة | `/` تسجيل الدخول، `/register` الاستمارة، `/member` صفحة العضو، `/vote` التصويت |
| لوحة إدارة العضوية | `/admin` |
| لوحة لجنة الانتخابات | `/elections` |

اللوحتان منفصلتان تماماً: لكل منهما حساب مستقل وجلسة مستقلة، ولا تستطيع أي منهما الوصول إلى بيانات الأخرى أو وظائفها.

### ما تم استيراده

تم استيراد **378 عضواً** من الكشف الأصلي `اعضاء_الجمعية_العمومية.xlsx` عند أول تشغيل، مع معالجة ما يلي:

- **إعادة الأصفار المفقودة إلى الأرقام الشخصية.** كان Excel قد حذف الصفر الأول من 36 رقماً (مثال: `304450` أُعيد إلى `000304450`). جميع الأرقام الآن من تسعة أرقام.
- **تحويل تواريخ الميلاد** من الصيغة العربية (`نوفمبر ٦, ١٩٧١`) إلى تاريخ فعلي.
- **تحويل الأرقام العربية الهندية** (٠١٢٣٤٥٦٧٨٩) إلى أرقام لاتينية في كل الحقول الرقمية.

> **تنبيه:** في الكشف الأصلي توجد ثماني مجموعات من الأعضاء تشترك في رقم هاتف واحد (أفراد أسرة واحدة). تم الإبقاء عليهم كما هم، ويُمنع التكرار على الطلبات الجديدة فقط. الدخول يبقى دقيقاً لأن الرقم الشخصي فريد لكل عضو.

## التشغيل عبر Docker

```bash
# 1) تجهيز كلمات المرور
cp .env.example .env
nano .env          # غيّر كلمتي المرور

# 2) التشغيل
docker compose up -d --build

# 3) متابعة السجل
docker compose logs -f
```

يستمع النظام على `127.0.0.1:8080`. ضع أمامه خادماً عكسياً لإنهاء TLS، مثال Nginx:

```nginx
server {
    listen 443 ssl http2;
    server_name membership.example.org;

    ssl_certificate     /etc/letsencrypt/live/membership.example.org/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/membership.example.org/privkey.pem;

    client_max_body_size 8m;   # صور المرشحين

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

> استخدام HTTPS ضروري. عند `COOKIE_SECURE=true` لا يُرسل المتصفح ملف الجلسة عبر اتصال غير مشفّر، فلن يعمل تسجيل الدخول على `http://` عدا `localhost`.

### التشغيل بدون Docker

```bash
go build -o matam .
DATA_DIR=./data LISTEN_ADDR=:8080 COOKIE_SECURE=false \
ADMIN_PASSWORD=... ELECTIONS_PASSWORD=... ./matam
```

## متغيرات الإعداد

| المتغير | الافتراضي | الوظيفة |
|---|---|---|
| `DATA_DIR` | `./data` | قاعدة البيانات والصور وملف التصدير |
| `LISTEN_ADDR` | `:8080` | عنوان الاستماع |
| `COOKIE_SECURE` | `false` | اجعله `true` في الإنتاج |
| `MAX_UPLOAD_MB` | `5` | الحد الأقصى لحجم صورة المرشح |
| `REGISTER_LIMIT_PER_HOUR` | `40` | عدد الطلبات المسموحة من عنوان شبكة واحد في الساعة |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | `admin` / عشوائية | حساب إدارة العضوية، عند أول تشغيل فقط |
| `ELECTIONS_USERNAME` / `ELECTIONS_PASSWORD` | `elections` / عشوائية | حساب لجنة الانتخابات، عند أول تشغيل فقط |
| `TZ` | `Asia/Bahrain` | التوقيت المستخدم في مواعيد الإغلاق |

إذا لم تُحدَّد كلمة المرور عند أول تشغيل، يولّدها النظام عشوائياً ويطبعها في السجل مرة واحدة. احفظها فوراً.

## الحسابان الإداريان

يُنشأ الحسابان عند أول تشغيل فقط، ولا يُعاد إنشاؤهما بعد ذلك حتى لو تغيّرت المتغيرات.
لتغيير كلمة المرور لاحقاً استخدم زر **تغيير كلمة المرور** داخل اللوحة نفسها؛ يتطلب إدخال كلمة المرور الحالية، وتُلغى بقية الجلسات المفتوحة تلقائياً.

## دليل الاستخدام

### لوحة إدارة العضوية — `/admin`

| التبويب | الوظيفة |
|---|---|
| **طلبات العضوية** | مراجعة الطلبات الواردة، اعتمادها أو رفضها أو حذفها. لا يُنشأ حساب للعضو إلا بعد الاعتماد. |
| **الأعضاء** | البحث في كشف الأعضاء، تعديل بيانات أي عضو، أو حذفه. الحذف يزيله من قاعدة البيانات ومن ملف Excel معاً. |
| **تحرير الاستمارة** | تعديل العنوان والشروط ونص الإقرار، تعديل مسميات الحقول، وإضافة حقول جديدة أو حذفها أو إعادة ترتيبها. |
| **التسجيل والتصدير** | فتح التسجيل أو إغلاقه فوراً أو تحديد موعد إغلاق مستقبلي، وتنزيل كشف الأعضاء. |

**الحقول المحمية:** الاسم والرقم الشخصي وتاريخ الميلاد ورقم التواصل لا يمكن حذفها ولا تعطيلها، لأنها بيانات الدخول نفسها. يمكن تغيير مسمياتها ونصوصها الإرشادية.

**موعد الإغلاق المجدول** يظهر تلقائياً في شريط أعلى صفحة التسجيل.

**التصدير:** أي اعتماد أو تعديل أو حذف يعيد بناء ملف `اعضاء_الجمعية_العمومية.xlsx` داخل مجلد البيانات مباشرة. الأرقام الشخصية مخزّنة بصيغة نصية، فلا يحذف Excel الصفر الأول لا عند الفتح ولا عند إعادة الحفظ.

### لوحة لجنة الانتخابات — `/elections`

| التبويب | الوظيفة |
|---|---|
| **إعداد التصويت** | اختيار نظام التصويت، عنوان الانتخابات ونص الإعلان، وإدارة المناصب. |
| **المرشحون** | إضافة المرشحين بالصورة والاسم والوصف، وتعديلهم أو حذفهم. |
| **النتائج** | عدد الأصوات والنسب والفائزون ونسبة المشاركة. |

**نظاما التصويت:**

- **حسب المناصب** — لكل منصب صفحة مستقلة، ويتنافس فيه مرشحوه وحدهم. لكل منصب عدد فائزين مستقل (مثال: رئيس واحد، وعضوان لمجلس الإدارة) وعدد اختيارات مستقل.
- **قائمة واحدة** — جميع المرشحين في صفحة واحدة، مع عدد فائزين وعدد اختيارات موحّد.

**حالات التصويت:** `إعداد` لا يظهر شيء للأعضاء ← `مفتوح` يظهر الإعلان ويُستقبل التصويت ← `مغلق` تتوقف الأصوات وتثبت النتائج.

النظام يمنع فتح التصويت إذا كان أحد المناصب بلا مرشحين، أو إذا كان عدد الاختيارات المسموحة أكبر من عدد المرشحين فيه.

**سرية النتائج:** عدد الأصوات والنسب لا تُرسل إطلاقاً إلى صفحات الأعضاء ولا إلى لوحة إدارة العضوية. البيانات التي تصل إلى متصفح العضو تحتوي على أسماء المرشحين وصورهم فقط.

### تجربة العضو

1. يدخل بـ **رقم الهاتف + تاريخ الميلاد + الرقم الشخصي** المسجّلة.
2. غير المسجّل يُوجَّه إلى الاستمارة، وبعد الإرسال تظهر رسالة `لقد تم ارسال طلب التقديم بنجاح`.
3. العضو المعتمد قبل إعلان الانتخابات يرى: `لا يوجد شيء حتى الآن، بانتظار الاعلان من لجنة الانتخابات`.
4. عند فتح التصويت يظهر زر الدخول إلى ورقة التصويت، مع مراجعة الاختيارات قبل الإرسال النهائي.
5. لا يمكن التصويت أكثر من مرة واحدة.

## النسخ الاحتياطي

كل شيء داخل مجلد البيانات (`/data` في الحاوية).

```bash
# نسخة احتياطية سليمة أثناء التشغيل
docker compose exec matam sh -c 'sqlite3 /data/matam.db ".backup /data/backup.db"' 2>/dev/null \
  || docker compose stop matam
docker run --rm -v matam-data:/data -v "$PWD:/backup" debian:bookworm-slim \
  tar czf /backup/matam-$(date +%F).tar.gz -C /data .
docker compose start matam
```

أبسط طريقة يومية: نزّل ملف Excel من لوحة إدارة العضوية واحتفظ به. لكنه لا يشمل الأصوات ولا بيانات المرشحين، لذلك انسخ المجلد كاملاً قبل يوم الانتخابات وبعده.

## ملاحظات فنية

**الأمان**

- كلمات المرور مخزّنة بخوارزمية PBKDF2-HMAC-SHA256 بـ 210,000 دورة وملح عشوائي لكل حساب.
- الجلسات رموز عشوائية 256 بت مخزّنة في قاعدة البيانات، صلاحيتها 12 ساعة، وملفات الارتباط `HttpOnly` و`SameSite=Strict`.
- حماية من تزوير الطلبات عبر التحقق من مصدر كل طلب يغيّر البيانات.
- تحديد معدل المحاولات على التسجيل وعلى تسجيل الدخول.
- صور المرشحين تُفحص بمحتواها الفعلي لا بامتداد اسمها، مع منع الخروج من مجلد الرفع.
- ترويسات `Content-Security-Policy` و`X-Content-Type-Options` و`Referrer-Policy` مفعّلة.

**منع التصويت المزدوج** مضمون بقيد فريد على مستوى قاعدة البيانات، لا بفحص برمجي فقط، فلا يفلت حتى مع طلبين متزامنين.

**ملف Excel** يُكتب بمكتبة داخلية مبنية على المكتبة القياسية فقط. كل خلية تُكتب كنص صريح بتنسيق `@`، وهو ما يضمن بقاء الأصفار الأولى بعد الفتح وإعادة الحفظ. الورقة من اليمين إلى اليسار مع تثبيت صف العناوين ومرشّح تلقائي.

**التبعيات:** حزمة خارجية واحدة فقط هي مشغّل SQLite (`github.com/mattn/go-sqlite3`). لا توجد أي مكتبة خارجية في الواجهة.

**بنية المشروع**

```
main.go                  نقطة التشغيل، تضمين الواجهة وكشف الأعضاء داخل الملف التنفيذي
internal/store/          قاعدة البيانات: الأعضاء، الطلبات، الانتخابات، الحسابات، سجل العمليات
internal/auth/           تشفير كلمات المرور ورموز الجلسات
internal/xlsxw/          كاتب ملفات Excel
internal/httpapi/        المسارات والتحقق والصلاحيات
web/pages/               صفحات HTML
web/static/              التنسيقات والسكربتات
seed/members.json        الأعضاء 378 المستوردون من الكشف الأصلي
```
